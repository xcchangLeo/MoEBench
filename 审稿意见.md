Comments for authors about extended abstract
--------------------------------------------

The paper addresses a nice problem. Full benchmark suites are expensive to run repeatedly, and this matters for regression testing, cloud comparison, monitoring, and autotuning. The main idea is reasonable. BenchScout runs a small set of short probes selected using current host context, then reconstructs the full benchmark profile. This is better than execution-free prediction because it captures some target-host state.

The advance is not obviously large though. The pieces look familiar: conditional selection, short execution prefixes, and sparse reconstruction. The contribution depends on whether the combination is robust and practically useful across realworld deployment conditions.

The reported errors are very low, which is encouraging but also raises questions. I'd like to understand train/test splits, whether runs from the same host leak information, how well this handles unseen machines, kernel versions, contention, virtualization, hardware faults, and workload regressions.

I would also like better baselines. Static subsets, random subsets with the same probe budget, adaptive probing, matrix-completion baselines, and simple correlation-based reconstruction would help establish whether the learned pipeline is necessary.

After re-reading a few times, I think I understand the main ideas a bit better, especially in terms of conditional selection and short-duration probing. It is not clear to me how novel these ideas are. But the results are quite impressive, and the evaluation is thorough, covering multiple benchmark suites across a diverse set of platforms. Overall, the experimental evaluation is a strong point of the paper.
