# Route B 探针建模汇总（Micro-probe / Real-probe）

本文档归纳 MoEBench 中 **Route B（probe-only baseline）** 的两种探针模式如何建模，供论文插图与实验说明参考。

相关代码：`moebench/probe/`，CLI：`scripts/probe_collect.py`、`probe_train.py`、`probe_experiment.py`。

---

## 一、Route B 在整体架构中的位置

Route B **不走 router 选子集、也不走 reconstructor**，流程是：

```
对每个 subtest t_j（全量 probe，不筛选）
  → 固定时长探针（4s 默认）采集 telemetry
  → 监督回归器 f 预测该子项 full-run 分数 ŷ_{i,j}
  → 聚合所有子项 → suite 分数 Ŷ_i
```

两种探针模式的区别只在 **「如何产生观测」**；**监督目标始终是 historical full-run 的官方分数**。

---

## 二、共同框架（Micro / Real 共享）

### 2.1 输入与标签（离线建数据集）

对每台主机 `machine` 的历史 full-run JSON（`dataset/<session>/run-*.json`）：

| 项目 | UnixBench | PTS |
|------|-----------|-----|
| **标签 y** | 子项 index（`yi.tests[tid].index_detail.index`） | profile primary value |
| **Suite 标签** | `system_benchmarks_index_score` | 各 profile 的 log-mean |
| **标签变换** | 无（`none`） | `log(1+x)` |
| **Estimator** | **共享 1 个**回归器 + test one-hot | **每个 profile 独立**回归器 |

每个 `(run, test_id)` 样本 = **一次 live probe** + **该 run 的 full-run 标签**。

### 2.2 并行采集窗口（`collect_subtest_probe`）

固定墙钟预算 `duration_s`（默认 **4s**，范围 1–30s），三路并行：

```
┌─────────────────────────────────────────┐
│  Thread A: eBPF (bpftrace)              │  sched_switch / syscall_enter 计数
│  Main:    workload（micro 或 real）      │
│  末尾:    /proc 快照（~0.5s）            │  CPU util, page faults, loadavg
└─────────────────────────────────────────┘
         ↓
    probe dict → ProbeVectorizer → p_{i,j} ∈ R^d
```

### 2.3 特征向量 **p**（19 维基础 + 可选 one-hot）

`ProbeVectorizer` 固定 19 维：

| 维度组 | 特征 | 含义 |
|--------|------|------|
| 元信息 | `probe_duration_s`, `wall_s`, `workload_rc` | 预算、实际耗时、负载退出码 |
| eBPF | `sched_switch_per_s`, `syscall_per_s`, `ebpf_available` | 调度/系统调用速率；不可用时置 0 |
| /proc | `proc_cpu_{user,system,idle}`, `proc_minor/major_faults` | CPU 利用率、缺页 |
| 类别 | `cat_{cpu,memory,io,thread,syscall,gpu}` | test_id → category 的 one-hot |
| Real 专用 | `real_run`, `real_timed_out` | 是否跑真实 benchmark；是否被 timeout 杀掉 |

**UnixBench 训练时**再拼接 **12 维 test one-hot** → 共 **31 维**。

**PTS 训练时**不拼 one-hot（per-test 模型已按 profile 分开）。

### 2.4 监督回归器

- **模型**：LightGBM 或 XGBoost（`MultiOutputRegressor` 包一层，输出标量）
- **UnixBench**：`ŷ = f(p, onehot(t_j))` — 一个共享 `f`
- **PTS**：`ŷ_j = f_j(p)` — 每个 profile 一个 `f_j`（至少 3 条样本才训练）
- **推理**：PTS 先 `expm1` 反变换回 primary value

### 2.5 Suite 聚合

对所有子项预测 `{ŷ_j}`：

- UnixBench：`geomean_index` = `expm1(mean(log1p(ŷ_j)))`
- 与 full-run suite index 比相对误差

## 三、Micro-probe 建模（默认 Route B）

### 3.1 核心思想

**不跑** UnixBench/PTS 官方子项，只跑 **MoEBench 自设计的 category 微负载**，用 telemetry 去拟合 **真实 full-run 分数**。

### 3.2 流程

```
test_id  ──→  category 映射  ──→  category micro-workload（Python 子进程，跑满 duration_s）
                                      │
                                      ├─ CPU:     sqrt 循环
                                      ├─ memory:  64MB array 拷贝
                                      ├─ IO:      临时文件 64KB 读写
                                      ├─ syscall: getpid 密集调用
                                      ├─ thread:  subprocess spawn(true)
                                      └─ gpu:     大 float array + sqrt（CPU 模拟）
                                      │
                    同时 eBPF + /proc 采样
                                      ↓
                              p^Micro_{i,j}
                                      ↓
                    ŷ_{i,j} = f(p^Micro_{i,j}, e(t_j))   [UnixBench 加 one-hot]
```

### 3.3 UnixBench category 映射（12 子项）

| Category | 子项示例 |
|----------|----------|
| CPU | dhry2reg, whetstone-double |
| IO | fstime, fsbuffer, fsdisk |
| thread | execl, pipe, context1, spawn, shell1, shell8 |
| syscall | syscall |

PTS 子项通过 `infer_pts_category(test_id, title)` 映射到同类 category（含 gpu 等）。

### 3.4 特点

- **快、稳、可控**：无 benchmark 初始化 / Perl / PTS 开销
- **real_run=0, real_timed_out=0**
- **workload_rc** = 微负载 Python 进程退出码
- 标签仍是 **官方 full-run index**，micro 分数本身 **不作为 y**

## 四、Real-probe 建模

### 4.1 核心思想

**跑真实 benchmark 二进制**，但用 **`timeout` 硬截断**；截断后的 telemetry（含 timeout 标志）去拟合 full-run 分数。

### 4.2 流程

```
test_id  ──→  真实 benchmark invocation（category 仅作特征 one-hot）
                                      │
         UnixBench: timeout perl Run -c 1 <test_id>
         PTS:       timeout phoronix-test-suite run <profile>
                                      │
                    通常 < duration_s 内跑不完 → timed_out=1，无有效 official score
                    同时 eBPF + /proc 采样（与 micro 相同窗口）
                                      ↓
                              p^Real_{i,j}
                    （含 real_run=1, real_timed_out∈{0,1}, workload_rc=timeout rc）
                                      ↓
                    ŷ_{i,j} = f(p^Real_{i,j}, e(t_j))
```

### 4.3 Real 专有 metadata（`real_run` dict）

- `elapsed_s`, `returncode`（124 = timeout）
- `timed_out`: bool
- `partial_result`: 若 report 已生成，可能有截断 score/index（**多数情况为空**）
- **标签仍来自 dataset full-run**，不用 partial_result 作 y

### 4.4 Micro vs Real 对比

| | Micro | Real |
|---|--------|------|
| 负载 | 自设计 category 脚本 | 官方 Run / PTS |
| 启动成本 | 低 | 高（spawn、加载、初始化） |
| 语义对齐 | 近似压力 | 真实二进制行为 |
| 特征差异 | `real_run=0` | `real_run=1`, 常有 `real_timed_out=1` |
| 论文动机 | 在线默认、Table probe 实验 | 高语义、高成本；昂贵 expert 可换 micro |

## 五、训练 vs 推理

### 5.1 离线训练

```
Historical full runs (dataset/)
    对每个 (run_i, test_j):
        live probe(mode=micro|real, duration=4s)
        label y_{i,j} ← full-run 官方分数
        存 probe_dataset.json
            ↓
    train_probe_bundle (LGBM / XGBoost)
            ↓
    probe_<suite>_<backend>.pkl
```

### 5.2 在线推理（Route B eval）

```
对当前系统，对每个 test_j:
    collect_subtest_probe(mode=训练时相同)
    ŷ_j = predict_subtest(bundle, probe, test_j)
Ŷ = aggregate_suite_index({ŷ_j})
与 full-run ground truth 比 relative error
```

**无 router、无 reconstruction、无 active refinement**。

## 六、建议的 Figure 结构（双路径对比图）

「共享头尾 + 中间分叉」：

```
                    ┌─── Historical full-run labels y_{i,j} ───┐
                    │         (supervision only)                │
                    ▼                                           │
┌──────────┐   ┌────────────────────────────────┐              │
│ test_id  │──→│  Category map (CPU/IO/thread/…)  │              │
└──────────┘   └────────────┬───────────────────┘              │
                             │                                  │
              ┌──────────────┴──────────────┐                  │
              ▼                             ▼                  │
     ┌─────────────────┐          ┌─────────────────┐         │
     │  MICRO branch   │          │  REAL branch    │         │
     │ category μ-load │          │ timeout(UB/PTS) │         │
     └────────┬────────┘          └────────┬────────┘         │
              └──────────────┬─────────────┘                  │
                             ▼                                  │
              ┌──────────────────────────────┐                 │
              │ Parallel 4s window:          │                 │
              │  • eBPF rates                │                 │
              │  • /proc snapshot            │                 │
              │  • flags (timeout, rc, cat)  │                 │
              └──────────────┬───────────────┘                 │
                             ▼                                  │
              ┌──────────────────────────────┐                 │
              │ ProbeVectorizer → p_{i,j}    │◄────────────────┘
              │ (+ test one-hot for UB)      │   train f / f_j
              └──────────────┬───────────────┘
                             ▼
              ┌──────────────────────────────┐
              │ LGBM / XGBoost regressor       │
              │  ŷ_{i,j} = f(p_{i,j}, e(t_j)) │
              └──────────────┬───────────────┘
                             ▼
              ┌──────────────────────────────┐
              │ Suite aggregate (geomean)    │
              │  Ŷ_i                         │
              └──────────────────────────────┘
```

**图例建议**：

- 实线框：两种模式共有
- 左分支：Micro（轻量 stimulus）
- 右分支：Real（真实 binary + timeout）
- 虚线：监督信号只来自 full-run，不来自 probe 本身

## 七、设计要点（论文 narrative）

1. **Observation ≠ Target**：micro/real 只决定如何采 `p`；`y` 永远是 full-run 官方分数（calibrated mapping）。
2. **Truncation as feature**：real 模式 timeout 不丢弃，编码进 `real_timed_out`。
3. **Graceful eBPF degradation**：`ebpf_available=0` 时仍可用 /proc + category 特征。
4. **Per-host training**：probe 模型只在当前主机 historical runs 上训练。
5. **Route B 成本**：`T_partial ≈ N × 4s`（N = 子项数）；论文 Table 中约 40–52s（含 eBPF、/proc 等开销）。

| 步骤 | 模块 / 脚本 |

| 实验 CLI | `scripts/probe_experiment.py` |

### 常用命令示例

```bash
# 采集 micro 探针数据集（UnixBench，本机）
python scripts/probe_collect.py \
  --benchmark unixbench \
  --probe-mode micro \
  --probe-duration-s 4.0 \
  --dataset-root dataset

# 训练 XGBoost 探针模型
python scripts/probe_train.py \
  --probe-dataset dataset/experiments/<machine>/probe_dataset.json \
  --model-out dataset/experiments/<machine>/probe_unixbench_xgb.pkl \
  --model-type xgboost
```
