# 一种基于执行锚定学习的基准测试套件加速方法及系统

## 技术领域

[0001] 本发明涉及计算机系统性能评估与机器学习技术领域，具体而言，涉及一种基于执行锚定学习的基准测试套件加速方法及系统，适用于 Linux 环境下 UnixBench、Phoronix Test Suite 等标准基准测试套件的快速评估、自动调优、回归测试及生产环境性能监测等场景。

## 背景技术

[0002] 基准测试套件通过在一组标准化工作负载上运行可重复的测量程序，对计算平台的处理器、内存、存储、系统软件及加速器等子系统性能进行量化表征，并输出各子项分数及聚合指标。该类套件广泛应用于云实例选型、性能监控、自动调优等工程流程。然而，基准测试套件通常采用“全量运行至完成”的执行模式：对包含 N 个子项的套件，需依次或并行执行全部子项，各子项按官方协议运行至完成，再经官方聚合函数得到整体指数。全量执行的墙钟时间与资源占用随子项数量及单项时长线性或超线性增长，在 UnixBench、Phoronix Test Suite CPU 等套件上可达数十分钟乃至数小时，在自动调优等需反复调用基准测试的场景中，评估开销往往占据任务总时间的主要部分。此外，全量执行会与同机共驻工作负载竞争 CPU、内存带宽、存储带宽等资源，改变被测系统的负载与频率状态，在共享生产环境中引入测量干扰。

[0003] 为降低开销，现有技术主要沿两条路径缩短测量路径。第一条路径为静态子集方法：人工选取固定的一组子测试项作为套件代表，以子集执行结果近似全量结果。但固定子集难以跨瓶颈类型泛化——面向 CPU 密集型实例选取的子集，在 I/O 或内存受限主机上可能遗漏关键瓶颈行为，导致聚合指标偏差较大。第二条路径为无执行预测方法：基于主机静态配置、公开规格或离线训练数据，训练机器学习回归模型，在不运行基准测试工作负载的情况下直接预测套件分数。该类方法虽可进一步缩短墙钟时间，但无法观测目标主机上的瞬时争用、内核与硬件状态，且在生产环境中性能计数器（PMU）、eBPF 追踪等遥测信号常因权限、租户隔离或虚拟化限制而缺失或失真，导致预测结果在分布漂移下不可靠。因此，在需要可信性能画像时，工程实践仍普遍回退至全量运行至完成模式，以牺牲时间与干扰为代价换取测量保真度。

[0004] 进一步分析表明，全量执行存在两类可被利用的结构化冗余。其一为子系统冗余：同一套件内多个子项虽表面异构，但往往映射至重叠的硬件子系统。例如 UnixBench 中整数运算、管道通信、系统调用等子项可能共同受操作系统调度与内存层次结构制约；文件系统相关子项之间亦高度相关。子项分数的相关性矩阵显示，部分 CPU 簇内 Pearson 相关系数可达 0.99 以上，而跨簇耦合显著减弱。这意味着在固定测量预算下，执行少量互补子项并重建其余子项，理论上足以暴露当前系统的主要性能边界。其二为时间收敛冗余：许多子项本质为迭代速率测试，其前缀执行阶段的速率趋势可在数秒内稳定，而官方协议要求的完整运行时长可能达数分钟；继续执行主要降低统计方差而非改变被测量的本质量。上述观察表明，全量运行并非在信息论意义上必要，关键在于如何在保留目标主机真实执行信号的前提下，以稀疏、有界的方式完成测量并恢复官方语义下的完整结果。

[0005] 现有技术尚未将“条件子集选择”“有界时长探针测量”与“稀疏结果重建”统一为面向标准套件语义的单遍（single-pass）流水线，也缺乏在 PMU/eBPF 不可用、探针超时等降级条件下仍可持续推理的特征化机制。因此，亟需一种在目标主机上保留有界真实执行、输出与官方聚合函数一致的套件指标、并将墙钟时间从小时级压缩至秒级的基准测试加速方案。

## 发明内容

[0006] 有鉴于此，本发明的目的在于提供一种基于执行锚定学习的基准测试套件加速方法及系统，以解决现有全量基准测试耗时过长、静态子集泛化性差、无执行预测在动态生产环境下不可靠等技术问题。

[0007] 依据本发明的第一方面，提供一种基于执行锚定学习的基准测试套件加速方法，所述方法包括：

[0008] 在目标主机上采集预运行系统上下文特征，得到系统上下文向量；

[0009] 调用经主机本地历史全量运行数据训练的路由模型，基于所述系统上下文向量对基准测试套件中各子项专家进行相关性评分，并选取 Top-K 个子项作为待测专家集合，其中 K 为部署时固定的正整数且 K 小于套件子项总数 N；

[0010] 对所述待测专家集合中的每一子项，在固定墙钟预算内执行有界时长探针，采集探针前缀遥测向量，并调用探针估计模型将所述探针前缀遥测向量映射为对应子项的官方全量运行分数估计值；

[0011] 将所述系统上下文向量、各子项的观测掩码、探针估计分数及探针墙钟时长组装为稀疏观测元组，输入经随机掩码增强训练的结果重建模型，输出全套件各子项分数估计向量及经官方聚合函数计算的套件聚合指数估计值。

[0012] 依据本发明的第二方面，提供一种基于执行锚定学习的基准测试套件加速系统，所述系统包括：

[0013] 特征采集模块，配置于目标主机操作系统侧，用于采集静态主机描述信息与动态预运行压力指标，并输出系统上下文向量；

[0014] 路由模块，用于基于系统上下文向量对专家池中的各基准测试子项进行条件评分并输出 Top-K 待测专家集合；

[0015] 探针探测模块，用于在固定墙钟预算内对所选子项执行微探针或真实子项有界探针，并采集探针前缀遥测向量；

[0016] 探针估计模块，用于将探针前缀遥测向量映射为各子项的官方全量运行分数估计值；

[0017] 结果重建模块，用于基于稀疏观测元组对未执行子项分数及套件聚合指数进行补全预测；

[0018] 模型存储模块，用于存储按主机本地训练并持久化的路由模型、探针估计模型及结果重建模型检查点。

[0019] 依据本发明的第三方面，提供一种计算机可读存储介质，所述计算机可读存储介质中存储有计算机可执行指令，当所述计算机可执行指令被处理器执行时，实现前述的基于执行锚定学习的基准测试套件加速方法。

[0020] 与现有技术相比，本发明具有以下有益效果：

[0021] 本发明将基准测试加速问题建模为“条件稀疏测量加稀疏重建”，而非完全去除执行的离线回归，从而在大幅缩短墙钟时间的同时保留目标主机上的有界真实执行信号，使估计结果能够反映瞬时争用与运行时状态。

[0022] 本发明引入主机本地训练的路由模型，使 Top-K 子项选择随系统上下文动态变化，克服固定子集在不同瓶颈类型主机间迁移性差的问题。

[0023] 本发明采用固定墙钟预算的有界时长探针及探针至分数估计模型，利用子项分数的前缀收敛特性，将单个子项测量成本从“运行至完成”压缩为秒级探针，同时通过将 PMU 不可用、eBPF 降级、探针超时等异常编码为一等特征而非硬失败，保证在受限云内核与共享生产环境中的可部署性。

[0024] 本发明采用随机掩码增强训练的结果重建模型，从包含系统上下文、观测掩码、探针估计分数及探针时长的稀疏元组中恢复全套件官方语义下的子项分数与聚合指数，使输出指标与全量运行使用相同的官方聚合函数，便于与既有调优、回归及对比流程对接。

[0025] 在异构 Linux 主机上对 UnixBench 与 Phoronix Test Suite 的实验表明，本发明可将墙钟时间从数十分钟至数小时量级压缩至约 15 秒，使用全量执行时间的 0.067%–1.06%，同时使套件聚合指数的平均相对误差维持在约 0.2% 量级。

## 具体实施方式

[0028] 下面结合附图及具体实施方式，对本发明作进一步详细描述。应当理解，以下实施方式中所述步骤、模块划分及参数取值仅为说明本发明原理的示例，本领域技术人员在不脱离本发明精神和范围的前提下，可对步骤顺序、模型类型及特征维度进行等同替换或组合。

[0029] 图1示出了本发明实施例提供的整体架构。该架构在逻辑上包括四个串联阶段及三类离线训练模型，在目标主机上单次前向执行即可完成推理，不设自适应二次探针循环。各阶段如下：

[0030] **阶段一：特征采集（Profile）。** 特征采集模块在基准测试正式探针执行之前，对目标主机进行预运行上下文采集，输出系统上下文向量 **x**。采集过程包括：读取静态主机描述信息 **x^static**，涵盖 CPU 拓扑、NUMA 布局、内存容量、存储与挂载信息、内核版本、编译器版本、GPU 清单等；执行时长约 3 秒的预热工作负载以稳定调度状态；以约 0.5 秒间隔采样 **/proc** 文件系统中的动态压力指标 **x^dynamic**，包括 CPU/GPU 利用率、I/O 等待、平均负载、可运行任务数、缺页率等；在权限允许时通过 **perf** 读取 PMU 微架构指标（如 IPC、每周期指令数、缓存与分支缺失率等），并归一化为每秒速率；当 **perf** 或 eBPF 不可用时，记录可用性降级标志并对相应维度零填充，而非终止流水线。系统上下文向量 **x** 由 **x = [x^static, x^dynamic]** 拼接而成，经域感知特征工程处理后，形成约 80–120 维的定长浮点向量，供后续路由与重建模块使用。

[0031] **阶段二：条件路由（Route）。** 路由模块维护与基准测试套件子项一一对应的专家池 **E = {e_1, e_2, …, e_n}**。给定系统上下文向量 **x**，路由模型 **f_θ** 为每个专家 **e_i** 计算相关性得分 **s_i = f_θ(x, e_i)**，并经 softmax 归一化得到选择概率 **p_i**。路由模块选取概率最高的 Top-K 个专家构成待测集合 **S_K(x)**，其中 K 在部署时固定（例如 K=3），以保证墙钟预算可预测。路由模型仅依赖预运行上下文 **x** 进行决策，不观测探针结果，从而保持“采集→路由→探针→重建”的因果顺序。路由模型在离线阶段使用同一主机上 M 次完整全量运行的历史数据训练：每次运行记录 **(x_i, y_i)**，其中 **y_i** 为官方子项分数向量；LightGBM 排序模型以 **(x, e_i)** 对为样本、以 **y_i** 为标签优化 pairwise 排序损失；多层感知机（MLP）或图神经网络（GNN）专家路由模型则以 **x** 为输入、输出长度为 n 的 logit 向量并优化交叉熵。每台主机独立训练并持久化路由检查点，推理时不跨主机共享权重。

[0032] **阶段三：有界时长探针（Probe）。** 对 **S_K(x)** 中每个被选中的专家 **e_j**，探针探测模块在固定墙钟预算 **T_probe**（默认 4 秒，可配置范围为 1–30 秒）内并行执行三类活动：（1）eBPF 采样线程（在 **bpftrace** 可用时统计调度切换率、系统调用进入率等）；（2）工作负载刺激线程，按探针模式执行微探针或真实探针；（3）探针窗口末尾约 0.5 秒的 **/proc** 快照。微探针将专家映射至 CPU、内存、I/O、线程、系统调用、GPU 等粗粒度类别，并运行轻量合成刺激——例如 CPU 类执行 tight sqrt 循环、内存类执行数组拷贝、I/O 类执行临时文件读写、系统调用类执行 getpid 密集循环等；真实探针则调用官方子项二进制并在硬超时约束下运行。探针前缀遥测向量 **p_j** 采用固定 19 维模式，包含配置时长、实际墙钟时长、退出码、eBPF 速率、CPU 利用率、缺页统计、类别 one-hot 编码、微探针/真实探针/超时标志等。探针估计模型 **f_{e_j}** 将 **p_j**（必要时附加子项身份 one-hot）映射为官方全量运行分数估计值 **ŷ_j**；训练目标为最小化 **(ŷ_{i,j} - y_{i,j})²**，标签 **y_{i,j}** 始终取自历史完整运行的官方分数（UnixBench 为 Index 分数，Phoronix Test Suite 可对 primary 值取 log(1+x) 变换）。当 eBPF 不可用、探针超时或 PMU 被阻断时，相应标志位置位、特征维度零填充，样本仍参与训练与推理，使模型学习在降级遥测下的鲁棒映射。

[0033] **阶段四：稀疏重建（Reconstruct）。** 结果重建模块接收稀疏观测元组 **Z**。对每个专家 **e_i** 构造三元组 **z_i = (m_i, v_i, τ_i)**：**m_i** 为观测掩码（被路由选中且完成探针估计时为 1，否则为 0）；**v_i** 为分数值（观测槽位填入 **ŷ_j**，未观测槽位填 0）；**τ_i** 为探针墙钟时长（未观测填 0）。重建输入 **X = [x, m_1, v_1, τ_1, …, m_n, v_n, τ_n]**。结果重建模型 **g_φ** 输出全子项估计向量 **ŷ** 及套件聚合指数 **Ŷ = A(ŷ)**，其中 **A(·)** 为各套件官方聚合函数——UnixBench 采用对子项 Index 的几何均值规则，Phoronix Test Suite CPU/GPU 套件采用 profile primary 值的 log-mean 聚合。重建模型在离线阶段对历史全量运行进行随机掩码数据增强：每次从完整标签 **y_i** 中随机选取 1 至 n 个子项作为“已观测”，其余子项掩码置 0，使模型在训练时见到多样化稀疏模式，包括推理阶段由路由诱导的固定 Top-K 模式。损失函数为 **L_recon = ||ŷ - y||² + (Ŷ - Y)²**。重建器实现包括 XGBoost/LightGBM 多输出独立回归器及共享 trunk 的多头 MLP，均按主机本地数据训练并持久化。

[0034] 图2示出了结果重建模型的离线训练流程。训练数据来源于目标主机上多次完整全量基准测试运行的历史记录，每次记录包含系统上下文 **x**、官方子项分数向量 **y** 及套件聚合指数 **Y**。在训练样本构造阶段，对每次完整运行施加随机掩码：随机确定观测子集大小 k（均匀分布于 1 至 n），将被选中子项的掩码 **m_i** 置 1、分数 **v_i** 置为真实 **y_i**、时长 **τ_i** 置为对应探针时长或缺省值；未选中子项的 **m_i=0, v_i=0, τ_i=0**。增强后的稀疏样本与原始完整标签共同输入结果重建器，经前向传播得到预测 **ŷ** 与 **Ŷ**，再与原始 **y**、**Y** 计算重建损失并反向更新参数。该训练方式使重建器学习从部分观测与系统上下文中补全相关子项及聚合指数，而非记忆固定子集。

[0035] **在线推理协议。** 部署完成后，在目标主机上执行一次加速评估的流程为：（S1）调用特征采集模块，耗时约 **T_x ≈ 3** 秒，得到 **x**；（S2）加载主机本地路由检查点，计算 **S_K(x)**；（S3）对 **S_K(x)** 中每个专家依次或并行执行时长 **T_probe** 的探针，经探针估计模块得到 **K** 个 **ŷ_j**；（S4）组装 **Z** 并调用结果重建模块，输出 **ŷ** 与 **Ŷ**。总墙钟时间近似 **C_partial ≈ T_x + K·T_probe + T_infer**，其中 **T_infer** 为毫秒至亚秒级模型前向时间，远小于 **C_full = Σ C_i(T_i)** 的全量运行成本。默认配置 K=3、T_probe=4s 时，总时长约 15 秒，相对 UnixBench 全量运行（约 1500–1700 秒）及 PTS-CPU 全量运行（约 12000–27000 秒）可实现两个数量级以上的加速。

[0036] **离线训练协议。** 在每台目标主机上，首先通过官方协议多次完整运行基准测试套件（例如 UnixBench 采用 `perl Run -c 1`，Phoronix Test Suite 按 profile 完整执行），每次运行采集 **x**、**y**、**Y** 及各项墙钟时间，存入本地数据集。典型规模为每套件每主机 15–60 次标注会话。随后分模块训练：（1）路由模型，输入 **(x, y)**；（2）探针估计模型，对历史运行中每个 **(run, 子项)** 回放或在线采集 **T_probe** 窗口探针 **p**，以官方 **y_{i,j}** 为监督；（3）结果重建模型，对 **(x, y, Y)** 施加随机掩码增强。三台模型均按主机 slug 独立存储于本地模型目录，推理时不进行跨主机权重迁移，以隔离硬件分布差异。

[0037] **实施例一：UnixBench 单副本系统基准测试加速。** 专家池包含 N=12 个子项：**dhry2reg**、**whetstone-double**、**execl**、**fstime**、**fsbuffer**、**fsdisk**、**pipe**、**context1**、**spawn**、**syscall**、**shell1**、**shell8**，分别覆盖 CPU 内核、文件系统 I/O 及 OS/进程交互负载。在五台异构 Linux 主机（2U8G 至 32U128G）上，采用 LightGBM 路由、LightGBM 探针估计与 XGBoost 重建的组合，K=3、T_probe=4s、微探针模式，对留出测试运行进行离线回放评估。相对全量运行的 System Benchmarks Index Score，五台主机平均相对误差分别为 0.19%、0.30%、0.66%、0.19%、0.32%，墙钟时间约 15.0–15.1 秒，约为全量时间的 0.9%–1.0%。路由模块在 CPU 簇与文件系统簇间动态切换所选专家，使重建器能在不同 sysctl 配置与负载状态下恢复官方聚合指数。

[0038] **实施例二：Phoronix Test Suite CPU 套件加速。** 专家池包含约 13 个 CPU profile（含内核编译、加密、压缩、数值内核等）。探针估计与重建模块对 primary 吞吐量/时延指标采用 **log(1+x)** 变换，聚合函数采用 log-mean（式中 **A_logmean(v) = exp((1/N)Σ log(1+v_j)) - 1**）。在同一五主机测试床上，本发明相对全量 PTS-CPU 聚合分数的平均相对误差为 0.02%–0.38%，墙钟时间约 15 秒，而全量运行时间为 12450–15755 秒。与基于静态 CPU 规格的无执行 MLP 基线相比，后者在 PTS-CPU 上相对误差可达 85%–99% 以上，表明仅依赖静态特征无法捕获 I/O 与运行时争用，而本发明通过有界探针保留了目标主机执行信号。

[0039] **实施例三：Phoronix Test Suite GPU 套件加速（单 GPU 主机）。** 在配备 NVIDIA RTX 3090 Ti 的开发服务器上，对 PTS GPU compute 套件执行相同流水线；GPU 相关静态与动态特征在采集时写入 **x**，无 GPU 主机则对 GPU 维度零掩码。相对全量 GPU 套件聚合分数，平均相对误差约 0.18%，墙钟时间约 15 秒，全量参考时间约 27018 秒。该实施例说明本发明框架可扩展至含加速器的异构套件，仅需在专家池与特征向量中增加 GPU 类探针类别及对应 profile 映射。

[0040] **探针模式与降级行为说明。** 生产部署默认采用微探针模式以获得可预测延迟；当需要与官方二进制路径严格对齐时，可切换为真实探针模式，由 **timeout** 硬截断官方子项进程并记录 **real_timed_out** 标志。特征采集在 **perf** 事件组被 hypervisor 阻断时回退至 **/proc** 代理指标；eBPF 线程异常时设置 **ebpf_available=0** 并对 eBPF 维度零填充。上述降级路径均作为显式输入特征进入路由、探针估计与重建模型，保证流水线在受限权限云实例上仍可完成单次推理，而非因单一遥测缺失而整体失败。

[0041] **可选扩展：不确定度估计与主动 refinement。** 在一可选实施方式中，结果重建模型附加不确定度估计头，对套件聚合指数及各子项输出 **σ** 估计值，用于离线分析或主动 refinement 策略（在默认单遍流水线之外，按不确定度阈值追加探针）。该扩展不改变默认部署的单遍行为与固定 K、**T_probe** 预算，仅在需要更高置信度时可启用。

[0042] **系统部署形态。** 本发明所述系统可以软件工具链形式实现：包括特征采集子系统（**moebench** 采集模块）、路由训练与推理子系统、探针采集/训练/推理子系统、重建训练与推理子系统，以及将四阶段串联的混合评估流水线脚本。各模块通过主机本地 JSON 数据集与模型检查点目录解耦，支持按主机、按套件独立训练与版本管理。系统运行于 Linux 操作系统之上，依赖标准 **/proc**、可选 **perf**/**bpftrace** 及基准测试套件官方安装路径，无需修改套件官方计分语义。

[0043] 综上所述，本发明通过“预运行上下文采集—条件 Top-K 路由—有界时长探针至分数估计—随机掩码训练的稀疏重建”四阶段单遍流水线，在目标主机上保留有界真实执行的同时，将标准基准测试套件的墙钟评估成本压缩至秒级，并输出与官方聚合函数一致的子项分数与套件指数估计，有效支撑自动调优、回归测试及生产邻接性能监测等高频基准测试场景。
