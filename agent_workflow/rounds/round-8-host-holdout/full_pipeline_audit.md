# UnixBench whole-host pipeline audit

Source: `unixbench_full_pipeline_offline.json`, generated by
`scripts/run_host_holdout_hybrid_unixbench.py` on 2026-10-13. The JSON records
input SHA-256 hashes, outer and inner fold membership, selected components,
probe predictions, suite predictions, and per-run errors.

## Protocol

Each of five outer folds holds out all five May 2026 UnixBench runs from one
host. The other four hosts train the router, probe estimator, and reconstructor.
The reconstructor's training observations are probe predictions generated by
inner whole-host fits, then augmented across partial subsets. Held-out probe
telemetry was archived during the original full-run collection and is replayed
offline. The full-run suite index is used only as the test label. This is not a
fresh online or paired wall-time experiment.

Four K=3 policies share each outer fold's probe estimator and reconstructor:
learned context router, training-score-ranked fixed subset, first-three fixed
subset, and seeded random fixed subset. Thus policy comparisons isolate subset
choice under the same fitted models.

## Results

| Held-out host | Learned mean error | Score-ranked fixed mean error |
| --- | ---: | ---: |
| M1 | 40.44% | 40.44% |
| M2 | 14.66% | 14.66% |
| M3 | 7.99% | 7.99% |
| M4 | 4.52% | 4.52% |
| M5 | 7.76% | 7.75% |
| Mean of hosts | 15.07% | 15.07% |

The first-three and random fixed policies also average 15.07%. Different
policies select different subtests, yet suite predictions are exactly equal
across all four policies on every run of M1--M4. On M5 the largest inter-policy
spread is only 0.0791 index points. The fitted cross-host reconstructor is
functionally insensitive to selected probe observations in this evaluation;
this result does not establish that its output is mathematically context-only.

The archived selected-probe wall sums average 15.07 seconds (range
15.05--15.21 seconds). They exclude fresh context collection, orchestration,
and a paired full-suite run. Do not combine these timings with the whole-host
errors into an online speedup claim.

## Interpretation

This failed whole-host transfer limits the 0.21% median / 0.59% mean
run-held-out result from the one-session-per-host corpus. It provides no
evidence that learned routing beats fixed selection or that sparse probes
improve a new-host prediction. It should appear in the main paper, separately
from the oracle-component holdout, which supplies true component scores on the
test host and answers a different question.
